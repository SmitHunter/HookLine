# M2.5 Quality Pass Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn M2's working pipeline into one whose clips pass a measurable short-form quality bar: loud enough, readable, captioned through all speech, hooked in the first 3 s, paced, cleanly framed, and shipped with post copy.

**Architecture:** Fixes land in the existing modules. A new `hookline/quality.py` measures the bar automatically, and `hookline audit <job>` runs it so every render can be checked. The last task re-renders the podcast job and loops through independent audits until the bar passes or the remaining gaps are named.

**Tech Stack:** As M2. The new ffmpeg filters are `loudnorm` (two-pass), `acompressor`, `unsharp`, `zoompan`-free crop/scale zooms, and `signalstats`/static-band detection.

**Spec:** `docs/superpowers/specs/2026-10-17-hookline-design.md`. Inputs are the M2 audit findings (visual, selection, research) and `docs/superpowers/m2-backlog.md`.

## Quality Bar (the definition of "done")

Each rendered clip must pass all of these. `quality.py` checks them, except Q9–Q11, which are judged in Task 9's independent audit.

| # | Check | Pass threshold |
|---|---|---|
| Q1 | Integrated loudness | −14 LUFS ±1, true peak ≤ −1 dBTP |
| Q2 | Caption size | cap height of rendered caption text ≥ 55 px at 1080×1920 (measured on a frame) |
| Q3 | Caption coverage | a caption is on screen for ≥ 95% of the time any transcribed word is being spoken |
| Q4 | Safe zones | caption and hook text bounding boxes within x∈[60, 888], y∈[290, 1250] |
| Q5 | Hook title | ≤ 2 lines, ≤ 7 words, cap height ≥ 60 px, visible 0.0–3.0 s |
| Q6 | Opening | speech starts ≤ 0.5 s, and the first sentence is the pick's declared `first_words` |
| Q7 | Pacing | a framing change (cut or zoom step) at least every 5 s on single-shot layouts |
| Q8 | Encode | 1080×1920, H.264 yuv420p, video ≥ 5 Mb/s average, AAC 192k |
| Q9 | Framing | no false STACKED, no back-of-head/soft panel, no cropped burned-in graphics in frame |
| Q10 | Selection | each kept clip has verdict post/maybe; hook type declared; ends on payoff (not a backchannel) |
| Q11 | Packaging | sidecar has post caption (with a question), 3–5 hashtags, search title, all literally true to the clip |

## Global Constraints

- Everything from the M2 plan's Global Constraints still applies: Python 3.12/uv/ruff, list-arg subprocess, pathlib, atomic writes, one lossy final video encode, captions in sync with audio.
- Audio: there is exactly one lossy audio encode, so the intermediate's audio becomes PCM (`pcm_s16le` in `.mkv`). Loudness normalisation and AAC 192k happen in the final encode.
- Claude backend default stays `claude-code`. Selection schema changes must stay valid under structured-output limits: no numeric min/max, `anyOf` for nullables, `additionalProperties: false`.
- No re-transcription of existing DTW transcripts. The cache accepts old-format files with `timing == "dtw"` when the backend matches. The discrete GPU is down.

## Review Focus

1. **Silent or near-silent clips** (game audio only): loudnorm must not blow up noise. Cap gain at +20 dB and skip normalisation below −50 LUFS. Pinned in Task 1.
2. **Claude returns line numbers that don't exist or `first_words` that don't match:** fall back to time-based snapping and log once. The pick is never dropped for that reason alone. Pinned in Task 4.
3. **A clip with one long unbroken take and no cuts:** the zoom cadence still produces changes ≤ 5 s apart without nausea (zoom steps only, ≤ 1.2×, eased). Pinned in Task 6.
4. **Overlay detection on gameplay** (HUD, minimap): don't crop away real game content. Only bands static for ≥ 90% of samples AND touching the frame edge are treated as overlays. Pinned in Task 7.
5. **Every candidate verdict is skip:** the job exits 1 with a clear message, not a crash. Pinned in Task 4.

### Task 1: Loudness + single lossy audio encode

**Files:** Modify `media/ffmpeg.py` (`cut_segments`: intermediate audio `pcm_s16le`, container `.mkv`), `pipeline/render.py` (final encode audio chain), new `media/loudness.py`. Test: `tests/test_loudness.py`, `tests/test_render.py`.

**Interfaces:**
- `measure_loudness(path: Path) -> Loudness` (fields `i`, `tp`, `lra`, `thresh`, `offset`): runs pass 1 of `loudnorm=I=-14:TP=-1:LRA=11:print_format=json` and parses the JSON block from stderr.
- `loudnorm_filter(m: Loudness) -> str`: the pass-2 filter with `measured_*` values and `linear=true`. When `m.i < -50` it returns `"anull"`. It is preceded by `acompressor=threshold=-21dB:ratio=3:attack=5:release=120:makeup=2`, and the gain is capped by clamping `I` so that `I - m.i ≤ 20`.
- In the final encode, audio goes through `-af <chain>` then `-c:a aac -b:a 192k -ar 48000`.

- [ ] Tests:
  - A −30 LUFS sine-speech fixture renders to −14 ±1 LUFS with TP ≤ −1.
  - Near-silence (−60 LUFS) stays ≤ −40 LUFS (not boosted).
  - The intermediate is `.mkv` with `pcm_s16le`.
  - The final audio is AAC 192k.
- [ ] Implement. Run focused tests, then the full suite and ruff. Commit `feat: two-pass loudness normalisation to -14 LUFS, single lossy audio encode`.

### Task 2: Caption + hook sizing, coverage, safe zones

**Files:** Modify `captions/ass.py`, `media/subtitles.py` if needed. Test: `tests/test_captions.py`.

- Check whether the ASS PlayRes is honoured, and whether `original_size`/`force_style` is needed.

Fix the root cause. Write the cause in the report.

**Values:**
- **Cap style:** 1–3 words per line, uppercase, rendered cap height 64–72 px. Choose the Fontsize that achieves this, measured on a rendered frame.
- **Cap outline/shadow:** outline 10, shadow 4 (semi-transparent black).
- **Hook:** ≤ 2 lines × ≤ 18 chars, cap height ≥ 64 px, centred at y = 360. Background box uses `BorderStyle 3` in brand white text on black at 85% opacity. Fades out over 0.25 s ending at 3.0 s.
- **Coverage:** each caption group stays on screen until the next group starts, unless the gap is > 1.0 s. In that case it ends at word end + 0.3 s.
- **Safe zones** (Q4): caption centre y is clamped to [700, 1180]. Horizontal: max text width 828 px. Shrink with `\fscx\fscy` if a group's estimated width exceeds that.
- **Normalisation:** a newline in word text becomes a space. A trailing `\` cannot break `{\r}` — escape and test it.
- **Group breaks:** after `."`, `!"` and `?"` as well.

- [ ] Tests:

  - Hook ≤ 2 lines.

- [ ] Implement. Run focused tests, then the full suite and ruff. Commit `fix: captions and hook at intended size, no mid-speech gaps, safe zones`.

### Task 3: Transcript hygiene + cache migration

**Interfaces:**
- `dedupe_segments(words) -> list[Word]`: removes a run of words that repeats the immediately preceding run's text (normalised, 2–12 words) with overlapping or near-identical start times (≤ 0.3 s apart). This is a Whisper hallucination repeat, e.g. "We were a little older" ×2 or "It's epic" ×3.

- **Cache migration:** an old-format transcript.json whose `timing == "dtw"` is accepted when the current backend is whisper-cpp with a DTW preset. It is re-written in the new keyed format without re-transcribing. Log `transcript: migrated cached DTW transcript`.

### Task 4: Selection v2: line-indexed picks, hook discipline, verdicts, post copy

**Files:** Modify `pipeline/select.py`, `transcript_text.py` (numbered compact lines), `models.py` (ClipPick new fields), `pipeline/run.py` (sidecar). Test: `tests/test_select.py`, `tests/test_transcript_text.py`, `tests/test_pipeline.py`.

**Interfaces:**
- **Compact lines** become `L{n} [mm:ss.s] text ⟨markers⟩`. `n` is the sentence index into the full transcript (stable across chunks).
- **Schema per clip:**
  - `start_line`, `end_line` (int)
  - `cold_open_line` (int | null)
  - `first_words`, `last_words` (str)
  - `hook_type`: enum `bold_claim | surprising_fact | conflict | confession | question | in_progress_action | reaction_peak | story_peak`
  - `verdict`: enum `post | maybe | skip`
  - `title`, `hook_text`, `reason`, `scores` (as before)
  - `post_caption` (1–2 lines ending in a question)
  - `hashtags` (array of 3–5 strings without #)
  - `search_title` (keyword-first, ≤ 70 chars)
  - `category` (short string)
  - `comment_risk`: enum `low | medium | high`
  - `edit_beats`
- **Time mapping:** start = sentence[start_line].start, end = sentence[end_line].end, cold open = that sentence's span (≤ 5 s, else trimmed to its first 5 s on word boundaries).
- **Validation:**
  - Out-of-range lines → fall back to the nearest valid line and log once.
  - If `first_words` doesn't fuzzy-match (token overlap ≥ 0.6) the first sentence, search ±3 lines for a match and use it. Otherwise keep the line and log.
  - `verdict == "skip"` picks are dropped.
  - If every candidate is skip → `NoClipsSelectedError("Claude rated every candidate as skip — the source may not have strong moments")`.
  - Edit beats outside the clip are dropped.
- **`ClipPick` adds:** `first_words`, `last_words`, `hook_type`, `verdict`, `post_caption`, `hashtags: list[str]`, `search_title`, `category`, `comment_risk`. All optional with defaults, so old caches validate.
- **Sidecar:** gains these fields. `post_caption` comes from the pick rather than `hook_text`.
- **Allow fewer clips:** return only post/maybe picks, up to N. The too-few follow-up call only runs when fewer than N candidates were *returned* (not when fewer were kept after skips).
- **SYSTEM_PROMPT rewrite.** Keep the rubric weights, and add this guidance verbatim in spirit:
  - **Feed editor:** think like a feed editor, not a documentary editor. The first sentence must work for a stranger mid-scroll.
  - **`first_words`:** declare `first_words` (the verbatim first sentence heard). If it needs earlier context, move the start or use a cold open.
  - **Hook type:** pick one hook archetype per clip (list), one idea per clip.
  - **Ending:** end on the payoff line, never on "yeah"/"mm-hmm"/an interviewer backchannel. If the payoff lands within 15 s after your end, extend. Prefer endings that echo the opening so replays loop.
  - **Length:** prefer 20–40 s for talking heads. Use up to 60 s only if tension holds.
  - **`hook_text`:** 3–7 words, concrete nouns or numbers from the clip, literally true. Banned phrases: "Then this", "Wait for it", "You won't believe", "Watch till the end".
  - **Hot takes:** controversy, hot takes and confrontations are assets. `safety` penalises only slurs, sexual content and gore.
  - **Calibration:** hook ≥ 20 only if a stranger would stop scrolling on the first sentence alone. Most sources yield 1–4 postable clips. Use verdict skip honestly.
  - **Post copy:** `post_caption` ends with a question that invites comments. Hashtags are specific, not generic (#fyp banned). `search_title` leads with the searchable topic.
  - **Live streams:** chat-reading, sub/raid thank-yous and donation alerts are dead air. A loud reaction is the payoff: start 3–8 s earlier on the cause. When answering chat, put the question in `hook_text`.
  - **Comment risk:** flag `comment_risk` high when a clip invites creepy or harassing comments about the speaker's appearance.

- [ ] Tests:
  - Line mapping.
  - Out-of-range fallback.
  - `first_words` re-anchoring.
  - Skip dropping and all-skip error.
  - Out-of-clip edit beats dropped.
  - Schema has no numeric min/max and `additionalProperties` is false everywhere.
  - Prompt coverage needles for every guidance line above.
  - Sidecar includes post copy.
  - Chunk mode uses global line numbers.
- [ ] Implement. Run focused tests, then the full suite and ruff. Commit `feat: line-indexed selection with hook discipline, verdicts and post copy`.

### Task 6: Pacing zooms + sharpness + bitrate

**Files:** Modify `media/reframe.py`, `pipeline/render.py`, `media/ffmpeg.py` (`_ENCODER_QUALITY_ARGS`). Test: `tests/test_reframe.py`, `tests/test_render.py`.

**Interfaces:**
- `zoom_schedule(duration, cut_times, emphasis_times, max_gap=4.5) -> list[tuple[float, float]]` returns `(t, scale)` steps alternating 1.0 and 1.12. A step happens at each cut, at least every `max_gap` s (preferring sentence boundaries from remapped words), and a 1.2 punch at emphasis times, held 1.2 s then eased back over 0.3 s. Steps are eased over 0.2 s.
- `scene_filter` applies the schedule as a post-layout `scale`+`crop` zoom with expressions (centre-anchored; for FACE_TRACK anchored on the face centre). This applies to FACE_TRACK, FIT_BLUR (fg only) and SPLIT panels. On STACKED it applies to the facecam panel only.
- **Emphasis times:** from the pick's in-clip `edit_beats` that parse as `zoom: '<word>' @ <t>s` (source time → remapped).
- **Sharpening:** `unsharp=5:5:0.6:5:5:0.0` after any upscale > 1.3×.
- **Rate control:** libx264 `-crf 18 -maxrate 10M -bufsize 20M`; AMF `-rc cqp -qp_i 20 -qp_p 22 -qp_b 24`; NVENC `-cq 19`.

- [ ] Tests:
  - Schedule has no gap > 4.5 s and alternates.
  - Emphasis punch present.
  - A rendered 12 s FACE_TRACK clip has measurable scale changes (crop region differs between frames at t=1 and t=6 via frame diff on a static source).
  - Average bitrate ≥ 5 Mb/s on the testsrc fixture.
- [ ] Implement. Run focused tests, then the full suite and ruff. Commit `feat: eased zoom cadence on cuts and beats, sharpening, higher bitrate`.

### Task 7: Burned-in overlay detection

**Files:** Modify `media/reframe.py` (`detect_overlay_bands`), `pipeline/layout.py`/`render.py` (apply). Test: `tests/test_reframe.py`.

**Interfaces:**
- `detect_overlay_bands(video, crop=None) -> tuple[int, int] | None` returns `(top_cut_px, bottom_cut_px)`:
  - Samples 12 frames, using grayscale downscaled to 320 px wide.
  - Per row, the static score is the fraction of samples where the mean abs diff vs the median frame is < 4 AND the row edge density is > 0.08.
  - A band is a contiguous run of rows touching the top or bottom edge (within 4% of height), at most 30% of height, static in ≥ 90% of samples.
  - Returns pixel cuts in source scale, or None.
- **Applied as extra crop:** the crop's height shrinks to exclude the band before layout/reframe. Combine with `detect_crop`, and pass the combined crop to `plan_layouts` and `reframe_graph`.

- [ ] Tests:
  - testsrc2 with a static purple box + text drawn over the bottom 15% → bottom band ≈ 15% ±2%.
  - Moving content at the bottom → None.
  - Full static frame (paused video) → None, because it isn't a band.
- [ ] Implement. Run focused tests, then the full suite and ruff. Commit `feat: detect and crop burned-in lower-thirds and edge overlays`.
